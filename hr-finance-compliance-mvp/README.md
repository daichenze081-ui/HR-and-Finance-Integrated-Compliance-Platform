# PeopleLedger

**人力与财务一体化合规平台 — 黑客松演示原型**

PeopleLedger demonstrates one complete workflow: employee/payroll data → deterministic checks → report draft → finance review → director approval → evidence export. It is a working **browser-local prototype**, with Chinese UI and synthetic data. It does not yet implement the full feasibility proposal.

中文使用说明见 [快速开始](START_HERE.md)，录屏顺序见 [演示步骤](docs/DEMO_SCRIPT.md)。

## Run locally

Requires Node.js 20 or later. There are **no third-party runtime dependencies** and no installation step.

```sh
npm start
```

Open `http://127.0.0.1:4173`. Alternatively, `node scripts/serve.cjs` runs the same server. To select another port, set the `PORT` environment variable. The server binds to loopback and serves only `dist/`.

For a quick offline preview, open `dist/index.html` in a modern browser. Browser persistence for `file://` pages varies; the local server is preferred for recording and repeatable tests.

```sh
npm test
npm run check
```

The test suite covers exact monetary arithmetic, invalid/atomic imports, CSV handling, rule findings, approval order, historical snapshots, stale rule versions and persisted-data validation.

## Implemented

| Capability | Behavior |
| --- | --- |
| Employee and payroll records | Six fictional employees; edit fields with a required change explanation |
| CSV import | Preview then replace all records; strict schema, unique IDs, month and amount validation; up to 500 rows / 1 MB |
| Deterministic checks | Net-pay reconciliation, evidence reference, cost center, deductions range |
| Versioned report drafts | Captures record snapshot, rule version, issues and exact totals |
| Approval flow | Simulated finance review before director approval; required notes; director rejection |
| Stale report prevention | Data/rule changes require a fresh check and report; old snapshots retained |
| Exports | Payroll CSV, full JSON evidence package, browser print / Save as PDF |
| Local persistence | Refresh retains demo records in the same browser and origin |
| Responsive UI | Five working views, labelled controls, keyboard-friendly dialogs |

The fixture starts with three issues: `EMP-003` paid amount `4750` versus expected `4950`, missing evidence reference for `EMP-005`, and missing cost center for `EMP-006`.

## Explicit prototype boundaries

- Draft text is generated by deterministic local templates. **No live AI/model call is made.**
- The role selector simulates workflow actors. It is **not authentication or secure authorization**.
- Data and history reside in browser localStorage. They are editable by the browser owner, are not tamper-proof, and are not shared across users/devices.
- Evidence numbers are references only. No actual document upload or authenticity verification is implemented.
- Deductions are user-entered. CPF, tax and legal compliance calculations are not implemented; passing the four demo rules is not a legal compliance conclusion.
- AWS, Bedrock, Teams, MyCareersFuture, HRIS, ERP and regulator integrations are **not connected**. Recruitment, expenses, real file evidence, production identity and multi-user persistence remain future work.
- Use synthetic data. Do not upload real employee/payroll records to this prototype.

## Structure

```text
dist/
  index.html           Application shell and navigation
  styles.css           Responsive UI and print layout
  core.js              Pure validation, money, state transitions and exports
  app.js               Browser views, dialogs, import/export and local persistence
scripts/serve.cjs       Zero-dependency loopback HTTP server
tests/core.test.cjs     Meaningful workflow and integrity tests
examples/              Synthetic CSV examples
docs/ARCHITECTURE.md    Implemented design and future server boundary
docs/DEMO_SCRIPT.md     Exact demonstration steps
docs/AWS_NEXT_STEPS.md  Verified AWS hosting and future integration notes
START_HERE.md          Chinese quick start and GitHub upload checklist
```

`dist/` contains the authored static source, not generated/minified output. A small, optional read-only WebMCP summary is registered if supported by the browser; ordinary use does not depend on it.
