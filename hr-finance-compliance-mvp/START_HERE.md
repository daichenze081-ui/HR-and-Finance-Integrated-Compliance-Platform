# PeopleLedger 代码使用说明

这份代码实现了“员工与薪资 → 数据检查 → 报告草稿 → 财务复核 → 董事批准 → 证据导出”的可运行演示流程，可作为第 3 项 GitHub 仓库的起点，也可用于录制第 4 项视频。

## 打开演示

1. 解压代码包。
2. 想快速查看时，打开 `dist` 文件夹，双击 `index.html`。
3. 正式演示时，建议用 Node.js 20 或更新版本，在项目文件夹运行 `npm start`，然后打开 `http://127.0.0.1:4173`。无需安装项目依赖或填写密钥。

数据保存在当前浏览器中。不同浏览器、不同网址或不同端口的数据互不共享。若浏览器禁止保存，本次页面仍能操作，关闭前请导出证据包。

## 按这个顺序体验

1. 保持右上角角色为“HR 专员”，点击“运行数据检查”。
2. 修正三条记录，每次填写修改说明：
   - `EMP-003`：录入实付改成 `4950.00`。
   - `EMP-005`：凭证引用填 `PAY-202609-005`。
   - `EMP-006`：成本中心填 `CC-400`。
3. 再次运行检查，结果应为当前规则未发现异常。
4. 切换为“财务复核人”，进入“报告与审批”，点击“生成报告草稿”。
5. 点击“财务复核并提交”，填写复核意见。
6. 切换为“董事审批人”，点击“批准报告”，填写审批意见。
7. 进入“证据与记录”，下载 JSON 证据包或员工薪资 CSV。
8. 在报告页点击“打印 / 保存 PDF”，可利用浏览器打印功能保存报告。

详细讲解稿见 `docs/DEMO_SCRIPT.md`。演示完成后可用“重置演示数据”恢复初始状态；请先导出需要保留的记录。

## 放进 GitHub

1. 登录你自己的 GitHub 账号，新建仓库，例如 `people-ledger-compliance`。
2. 上传解压后的项目文件和文件夹，让 `README.md`、`package.json`、`dist` 等出现在仓库首页；不要只上传 ZIP。
3. 按比赛规则设置评委的访问权限。
4. 在 README 中补上真实团队编号、项目名称、视频地址及部署网址。
5. 复制仓库网页地址，作为邮件截图中的第 3 项。

GitHub 官方说明：[创建仓库](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)、[上传文件](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。

## 这个版本做到哪一步

金额检查、记录修改、CSV 导入、报告快照、审批状态和证据导出都实际执行。报告文字使用本地模板；AI 模型、AWS 服务、Teams 和政府系统尚未接入。角色切换用于演示，尚无真正的账号权限和服务器数据库。

因此，这份代码适合展示核心流程和技术思路，尚不是可处理真实员工资料的企业生产系统。若比赛要求必须实际调用 AWS 服务，需要继续按 `docs/AWS_NEXT_STEPS.md` 接入并验证。上传代码本身不能证明满足比赛全部规则。
